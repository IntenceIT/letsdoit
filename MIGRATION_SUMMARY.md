## 📋 What You Need to Do

### Step 1: Create Firebase Project
1. Go to [Firebase Console](https://console.firebase.google.com/)
2. Create a new project
3. Register a web app
4. Copy the configuration values

### Step 2: Update Environment Variables
Edit `.env` file and replace with your Firebase config:
```env
VITE_FIREBASE_API_KEY="your-actual-api-key"
VITE_FIREBASE_AUTH_DOMAIN="your-project-id.firebaseapp.com"
VITE_FIREBASE_PROJECT_ID="your-project-id"
VITE_FIREBASE_STORAGE_BUCKET="your-project-id.appspot.com"
VITE_FIREBASE_MESSAGING_SENDER_ID="your-sender-id"
VITE_FIREBASE_APP_ID="your-app-id"
```

### Step 3: Enable Firebase Services
1. Enable **Email/Password Authentication**
2. Create **Firestore Database** (production mode)
3. Set up **Security Rules** (provided in setup guide)

### Step 4: Create Admin User
1. Create user in Firebase Authentication
2. Create organization document in Firestore
3. Create member document linking auth user to organization
4. Set role to "admin"

**Detailed instructions in `FIREBASE_SETUP_GUIDE.md`**

### Step 5: Test Your Application
```bash
npm run dev
```

## 🔄 Database Structure Comparison

### Supabase (SQL) → Firebase (NoSQL)

| Supabase Table | Firebase Collection | Notes |
|----------------|---------------------|-------|
| `organizations` | `organizations` | Same structure |
| `members` | `members` | Same structure |
| `tasks` | `tasks` | Same structure |
| `task_assignments` | `task_assignments` | Same structure |

### Key Differences:
1. **No SQL Queries**: Use Firebase SDK methods instead
2. **No Triggers**: Implement logic in application code
3. **No Functions**: Use Firebase Cloud Functions if needed
4. **Document IDs**: Auto-generated by Firebase (not UUIDs)
5. **Timestamps**: Use Firebase `Timestamp` type

## 🔧 Backend (Node.js + Express)

The backend in `backend/` folder is **independent** and uses in-memory storage. It doesn't need changes for Firebase migration. However, if you want to integrate it with Firebase:

### Option 1: Keep Backend Separate (Current)

- Frontend uses Firebase
- No integration needed

### Option 2: Integrate Backend with Firebase
You would need to:
1. Install Firebase Admin SDK in backend
2. Update models to use Firestore
3. Update services to use Firestore
4. Configure Firebase Admin credentials

**Recommendation**: Keep them separate for now, or remove backend entirely if not needed.

## ⚠️ Important Notes

### Firebase is NOT SQL!
- No SQL queries - use Firebase SDK methods
- No JOINs - denormalize data or use client-side joins
- No triggers - implement in application code
- Collections and documents, not tables and rows

### Free Tier Limits
Firebase Spark Plan (Free):
- **Firestore**: 1 GB storage, 50K reads/day, 20K writes/day
- **Authentication**: Unlimited users
- **Bandwidth**: 10 GB/month

Perfect for your use case!

### Security
- Firestore security rules protect your data
- Rules are in `FIREBASE_SETUP_GUIDE.md`
- Test rules in Firebase Console

## 🐛 Troubleshooting

### "Permission denied" errors
→ Check Firestore security rules and ensure user is authenticated

### "Cannot find module '@/integrations/supabase'"
→ Restart your development server: `npm run dev`

### Environment variables not loading
→ Restart dev server after changing `.env`

### Firebase connection errors
→ Verify Firebase config in `.env` is correct
